# 示例与版式参照

> ⚠️ 说明：**SkillHub 只接受文本类文件，不接受图片**（.jpg/.png 会被服务端拒绝）。
> 所以本目录用 **SVG 矢量版式图 + 一份可跑的 demo 配置** 来表达"应该长什么样"。
> 真实成品图（带字幕的照片）在你自己的工作区里，见文末。

---

## 1. 版式示意（`版式示意.svg`）

用浏览器打开即可看。左边是**封面**版式，右边是**内容图字幕**版式，标注了关键尺寸。

| | 封面 | 内容图字幕 |
|---|---|---|
| 字号 | 标题 **画面宽 ×0.105**（Black）/ 副标题 ×0.042（Medium） | **×0.062**（Black） |
| 行数 | 标题 1–2 行 | 2–3 行，**均衡换行** |
| 底框 | 圆角，**只包住文字块** | 同左 |
| 位置 | 中心 **y≈0.33**（上 1/3 暗区） | 中心 **y≈0.80**（下方） |
| 关键 | 主体压下 2/3，上方留暗区 | 压在暗部，不挡脸 |

## 2. 可跑的 demo 配置（`demo_scenes.json`）

一个**完整的 4 帧例子**（《哑口隧道》，新闻改编 + 已去标识化），可直接拿来试：

```bash
mkdir demo && cp examples/demo_scenes.json demo/scenes.json
node scripts/gen_pack.mjs demo          # 拼提示词
# —— 出图，把图放进 demo/out/ ——
python scripts/burn_subtitles.py demo   # 内容图叠字幕
python scripts/make_cover.py demo       # 封面烧标题
node scripts/validate.mjs demo          # 验收
```

它演示了三件最容易做错的事：
1. `meta.topic_source` 怎么写（新闻改编的脱敏记录）
2. 封面帧怎么配（`id="00"` + `compo_variant:"cover"` + `meta.cover`）
3. 俯视帧怎么配（`compo_variant:"down"`，人物尺寸句要极小）

## 3. 常见"跑偏"长什么样（对照排查）

| 症状 | 哪里错了 |
|---|---|
| 字幕是**细体**、发飘 | 字重没生效 → `--font-weight Black`（默认就是） |
| 底框是**横贯全宽的长带** | 用了错工具；本 skill 的框只包文字 |
| 一行被硬切、标点跑到行首 | 换行/禁则没生效 → 确认用 `burn_subtitles.py` |
| 字幕糊在脸上 | `--y 0.84` 往下挪 |
| 封面没标题 / 标题很小 | 没跑 `make_cover.py`；或标题超过 8 字被压缩 |
| 画面里有中文乱码 | 有人让生图模型画字了——**中文只能后期烧** |
| 人物特别大、没有巨物感 | 没换陡俯视机位（机位决定占比，形容词没用） |

## 4. 真实成品图在哪

本 skill 打包时**不含照片**。跑完的项目里，成品在：

```
<项目目录>/out/subtitled/00_封面.png          # 封面
<项目目录>/out/subtitled/<帧号>_<标题>.jpg     # 内容图（已叠字幕）
```

自测建议：随便跑一帧，把 `out/subtitled/` 里的图和 `版式示意.svg` 对一眼——
**字号够不够粗、框有没有贴着字、两行是不是宽度接近**，三眼就能判断版式对不对。
